# Отчёт по лабораторной работе №3

## Текст задания

Вариант №36958: `Tutu.Ru` (`https://www.tutu.ru/`).

Необходимо:

- сформировать варианты использования сайта;
- разработать на их основе тестовое покрытие;
- провести функциональное тестирование интерфейса сайта;
- автоматизировать тестирование средствами Selenium;
- использовать XPath-селекторы для работы с динамически формируемыми элементами.

Примечание по реализации: вместо устаревшего Selenium RC используется `Selenium WebDriver 4`. Шаблон Selenium IDE приложен в формате `.side`.

## Область тестирования

Все варианты использования и тесты охватывают **только лендинговую страницу** `https://www.tutu.ru/`. Переход на дочерние домены (`avia.tutu.ru`, `hotel.tutu.ru` и др.) не является частью UC; проверяется взаимодействие пользователя с формами и блоками главной страницы.

## Детализированные прецеденты

### UC-01. Переключение вкладок сервисов меняет тип формы поиска

- Идентификатор: `UC-01`
- Уровень: пользовательская цель
- Основной актор: гость сайта
- Предусловия: открыта главная страница, виджет поиска загружен
- Триггер: пользователь хочет переключиться с авиабилетов на отели
- Основной успешный сценарий:
  1. Пользователь нажимает вкладку «Авиабилеты» — появляется блок выбора пассажиров.
  2. Пользователь нажимает вкладку «Отели» — форма структурно меняется: блок пассажиров исчезает, появляется виджет гостей/комнат.
  3. Пользователь возвращается на «Авиабилеты» — блок пассажиров снова появляется.
- Альтернативные потоки:
  1. A1: вкладка временно недоступна; интерфейс сохраняет текущую форму и не «ломается».
- Постусловия:
  1. Успех: активна выбранная вкладка, соответствующая форма отображается.
  2. Минимальные гарантии: предыдущая форма корректно скрыта.
- Спецтребования: визуальная смена формы без перезагрузки страницы.

### UC-02. Автодополнение при вводе названия города

- Идентификатор: `UC-02`
- Уровень: пользовательская цель
- Основной актор: гость сайта
- Предусловия: открыта вкладка «Авиабилеты» или «Ж/д билеты», форма активна
- Триггер: пользователь начинает вводить название города
- Основной успешный сценарий:
  1. Пользователь вводит фрагмент названия города (например, «Мос»).
  2. Система отображает выпадающий список подсказок.
  3. Список содержит хотя бы одну подходящую позицию.
  4. Пользователь выбирает первую подсказку.
  5. Поле заполняется полным названием города (не введённым фрагментом).
- Альтернативные потоки:
  1. A1: введённый фрагмент не совпадает ни с одним городом; система показывает сообщение «Ничего не найдено».
  2. A2: ответ автодополнения задержан более 2 секунд; система показывает индикатор загрузки.
- Постусловия:
  1. Успех: поле содержит корректное полное название города.
  2. Минимальные гарантии: поле доступно для повторного ввода.
- Спецтребования: список подсказок появляется не позднее чем через 2 секунды после ввода.

### UC-03. Кнопка «⇄» меняет местами города отправления и назначения

- Идентификатор: `UC-03`
- Уровень: пользовательская цель
- Основной актор: гость сайта
- Предусловия: заполнены оба поля — «Откуда» и «Куда»
- Триггер: пользователь хочет быстро поменять направление
- Основной успешный сценарий:
  1. Пользователь вводит «Откуда» = «Москва», «Куда» = «Санкт-Петербург».
  2. Пользователь нажимает кнопку обмена «⇄».
  3. Значения полей меняются: «Откуда» = «Санкт-Петербург», «Куда» = «Москва».
  4. Форма сохраняет дату и прочие параметры.
- Альтернативные потоки:
  1. A1: одно из полей пустое; кнопка недоступна или обмен приводит к пустому значению в соответствующем поле.
- Постусловия:
  1. Успех: значения полей поменялись местами.
  2. Минимальные гарантии: оба поля доступны для дальнейшего редактирования.
- Спецтребования: обмен выполняется мгновенно, без перезагрузки.

### UC-04. Навигация по месяцам в датапикере

- Идентификатор: `UC-04`
- Уровень: пользовательская цель
- Основной актор: гость сайта
- Предусловия: открыта вкладка «Авиабилеты», поле даты доступно
- Триггер: пользователь хочет выбрать дату в следующем месяце
- Основной успешный сценарий:
  1. Пользователь кликает на поле даты — открывается календарь.
  2. Пользователь читает заголовок текущего месяца (например, «Май 2026»).
  3. Пользователь нажимает кнопку «›» (следующий месяц) — заголовок меняется.
  4. Пользователь выбирает доступную дату в новом месяце.
  5. Поле даты заполняется выбранным значением; календарь закрывается.
- Альтернативные потоки:
  1. A1: максимальная доступная дата достигнута; кнопка «›» заблокирована.
- Постусловия:
  1. Успех: поле даты содержит дату из следующего месяца.
  2. Минимальные гарантии: датапикер закрыт, форма активна.
- Спецтребования: прошедшие даты недоступны для выбора (disabled-состояние).

### UC-05. Счётчик пассажиров обновляется при нажатии «+»/«−»

- Идентификатор: `UC-05`
- Уровень: пользовательская цель
- Основной актор: гость сайта
- Предусловия: открыта вкладка «Авиабилеты», форма поиска активна
- Триггер: пользователь летит группой и хочет указать количество пассажиров
- Основной успешный сценарий:
  1. Пользователь читает начальный текст кнопки пассажиров («1 пассажир»).
  2. Пользователь открывает панель выбора пассажиров.
  3. Пользователь нажимает «+» для взрослых дважды — счётчик внутри панели изменяется.
  4. Пользователь нажимает «Готово» / «Применить».
  5. Текст кнопки пассажиров обновляется («3 пассажира»).
- Альтернативные потоки:
  1. A1: достигнут максимум пассажиров; кнопка «+» становится disabled.
  2. A2: сумма пассажиров превышает допустимый лимит; система показывает подсказку.
- Постусловия:
  1. Успех: кнопка отражает выбранное количество пассажиров.
  2. Минимальные гарантии: значения не сбрасываются при закрытии/открытии панели.
- Спецтребования: счётчик обновляется мгновенно после каждого нажатия.

### UC-06. Переключение «В одну сторону» / «Туда-обратно» изменяет форму

- Идентификатор: `UC-06`
- Уровень: пользовательская цель
- Основной актор: гость сайта
- Предусловия: активна вкладка «Авиабилеты», по умолчанию выбран режим «В одну сторону»
- Триггер: пользователь планирует поездку туда-обратно
- Основной успешный сценарий:
  1. В режиме «В одну сторону» поле даты обратного билета не отображается.
  2. Пользователь нажимает «Туда-обратно» — на форме появляется второе поле даты.
  3. Пользователь нажимает «В одну сторону» — второе поле даты скрывается.
- Альтернативные потоки:
  1. A1: пользователь выбрал дату обратного вылета, а затем переключился в «В одну сторону»; система предупреждает о потере значения.
- Постусловия:
  1. Успех: форма отображает нужное количество полей дат.
  2. Минимальные гарантии: уже введённые данные (города, первая дата) сохраняются.
- Спецтребования: поле обратной даты появляется/скрывается без перезагрузки страницы.

### UC-07. Полное заполнение формы поиска отелей на лендинге

- Идентификатор: `UC-07`
- Уровень: пользовательская цель
- Основной актор: гость сайта
- Предусловия: открыта главная страница, доступна вкладка «Отели»
- Триггер: пользователь планирует забронировать отель
- Основной успешный сценарий:
  1. Пользователь переключается на вкладку «Отели» — форма меняется.
  2. Пользователь вводит город («Сочи») и выбирает из автодополнения.
  3. Пользователь нажимает поле даты заезда — открывается календарь.
  4. Пользователь выбирает дату — поле заполняется.
  5. Значение поля города сохранилось; форма готова к отправке.
- Альтернативные потоки:
  1. A1: дата выезда раньше даты заезда; система блокирует выбор и показывает ошибку.

  1. Успех: все поля формы заполнены корректными значениями.
  2. Минимальные гарантии: поля сохраняют значения при взаимодействии с другими элементами.

### UC-08. Пустой поиск вызывает визуальную ошибку на форме

- Идентификатор: `UC-08`
- Уровень: пользовательская цель (негативный путь)
- Основной актор: гость сайта
- Предусловия: открыта вкладка «Авиабилеты», поля «Откуда» и «Куда» пусты
- Триггер: пользователь случайно нажимает «Найти», не заполнив форму
- Основной успешный сценарий:
  1. Пользователь нажимает кнопку «Найти» с пустыми обязательными полями.
  2. Система не выполняет навигацию или выполняет её на страницу с ошибкой.
  3. Незаполненные поля подсвечиваются (красная рамка, сообщение об ошибке).
  4. Пользователь остаётся в контексте лендинга.
- Альтернативные потоки:
  1. A1: браузерная валидация HTML5 блокирует отправку ещё до перехода на сервер.
- Постусловия:
  1. Успех: URL либо не изменился, либо видна ошибка в интерфейсе.
  2. Минимальные гарантии: пользователь понимает, что и почему не заполнено.
- Спецтребования: сообщения об ошибках привязаны к конкретным полям.

### UC-09. Форма подписки — переход от невалидного состояния к готовности отправки

- Идентификатор: `UC-09`
- Уровень: пользовательская цель
- Основной актор: гость сайта
- Предусловия: блок подписки на email-рассылку доступен на странице
- Триггер: пользователь хочет подписаться на рассылку
- Основной успешный сценарий:
  1. Пользователь вводит email без символа «@» — браузер помечает поле как невалидное.
  2. Пользователь снимает галочку согласия (если была) и нажимает «Подписаться».
  3. Форма остаётся в ошибочном состоянии — данные не отправляются.
  4. Пользователь исправляет email на корректный формат — HTML5-валидация становится успешной.
  5. Пользователь ставит галочку согласия.
  6. Кнопка «Подписаться» активна; все условия для отправки выполнены.
- Альтернативные потоки:
  1. A1: email валиден, но чекбокс не отмечен; форма не отправляется, подсвечивается чекбокс.
- Постусловия:
  1. Успех: email валиден, согласие дано, кнопка активна.
  2. Минимальные гарантии: поле email сохраняет последнее введённое значение.
- Спецтребования: отображение ошибки и её исчезновение — без перезагрузки страницы.

### UC-10. Скролл до блока «Идеи для поездок» открывает карточки направлений

- Идентификатор: `UC-10`
- Уровень: пользовательская цель
- Основной актор: гость сайта
- Предусловия: открыта главная страница, блок «Идеи для поездок» существует ниже fold
- Триггер: пользователь изучает страницу и прокручивает её вниз
- Основной успешный сценарий:
  1. Страница открыта; блок «Идеи для поездок» за пределами viewport.
  2. Пользователь прокручивает страницу вниз до блока.
  3. Блок с заголовком «Идеи для поездок» попадает в область видимости.
  4. Отображается коллекция карточек направлений (минимум 2).
  5. Каждая карточка является кликабельной ссылкой с корректным `href`.
- Альтернативные потоки:
  1. A1: блок уже виден при загрузке (низкое разрешение); тест проходит без скролла.
- Постусловия:
  1. Успех: пользователь видит коллекцию карточек направлений.
  2. Минимальные гарантии: на странице есть хотя бы одна карточка с ссылкой.
- Спецтребования: блок должен лениво загружаться или быть доступен при scroll-trigger.
